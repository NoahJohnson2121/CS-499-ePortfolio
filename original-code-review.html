Original Travlr Getaways Code Review

Noah Johnson | CS-499

Overview

The Travlr Getaways application was originally developed as part of CS-465 Full Stack Development. It is a full-stack travel application that uses Angular for the client-side interface, Node.js and Express for the backend API, and MongoDB for data storage.

The application allows users to browse available trips, while authenticated users can perform administrative functions such as adding, updating, and deleting trip information.

The original application provided the core functionality required for the project, but the code review identified several areas that could be improved. The review focused on code structure, error handling, security, validation, database design, and maintainability.

Software Design and Engineering

The original application was organized into separate frontend and backend components, which provided a reasonable foundation for maintainability. The Express routes separated API endpoints from controller logic, while Angular components were responsible for displaying and interacting with trip data.

However, several areas could be improved. Some of the original backend code used basic error handling and returned database errors directly to the client. This could expose unnecessary implementation details and make responses less consistent. The API could also benefit from more standardized HTTP responses and clearer error messages.

Authentication and authorization were another area identified during the review. Administrative operations such as creating, updating, and deleting trips should be protected so that unauthorized users cannot modify application data.

The code also contained opportunities for improved documentation and consistency. Adding clearer comments and organizing repeated functionality would make the application easier for another developer to understand and maintain.

Planned Improvement

The planned enhancement was to improve the backend structure, error handling, authentication, validation, and documentation while maintaining the application's existing functionality.

Algorithms and Data Structures

The original application retrieved trips from MongoDB and displayed them to the user. The basic retrieval functionality worked, but there was limited functionality for efficiently locating specific trips from the user interface.

The application already used MongoDB queries to retrieve individual trips by their trip code. However, the user experience could be improved by providing a search capability that allows users to locate trips based on relevant information rather than requiring them to navigate through the entire list.

The code review also considered the structure of the application's data retrieval operations. Database queries should be appropriately targeted and should avoid unnecessary processing when possible.

Planned Improvement

The planned enhancement was to add search functionality that would allow users to more easily locate relevant trip information. This would demonstrate algorithmic problem solving and the practical application of data retrieval techniques.

Databases

The original application used MongoDB with Mongoose to store and manage trip information. The database structure provided the necessary fields for displaying destinations, including the trip code, name, length, resort, price, image, and description.

The review identified opportunities to improve data integrity through stronger schema validation. Some fields had limited restrictions on the values that could be stored, which could allow incomplete or inconsistent data to enter the database.

The original schema also provided an opportunity to improve database performance and reliability through appropriate indexing and constraints. For example, trip codes should uniquely identify individual trips and therefore are appropriate candidates for a unique database index.

Another consideration was the data type used for the price field. Storing prices as strings limits the ability to perform numeric operations or comparisons on the data. Improving the schema would make the database more consistent and easier to work with in future functionality.

Planned Improvement

The planned database enhancement was to strengthen the Mongoose schema through validation, data integrity rules, appropriate indexing, and improved data types where appropriate.

Overall Code Review Findings

The original Travlr Getaways application successfully implemented its core requirements, but the review demonstrated that functioning software can still have opportunities for improvement.

The primary areas identified were security, error handling, validation, database integrity, maintainability, functionality, and data handling.

These findings provided the foundation for the enhancements completed during CS-499. Rather than completely rewriting the application, the goal was to make targeted improvements that addressed weaknesses identified during the code review while preserving the application's existing functionality.

Skills Demonstrated

This code review demonstrates my ability to analyze existing software from a professional perspective, identify limitations, evaluate security and data concerns, and develop a practical enhancement plan.

It also demonstrates the transition from simply creating software that works to evaluating software based on maintainability, security, reliability, efficiency, and user experience.
