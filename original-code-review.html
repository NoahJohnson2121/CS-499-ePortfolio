Overview

The Travlr Getaways application was originally developed as part of CS-465 Full Stack Development. It is a full-stack travel application that uses Angular for the client-side interface, Node.js and Express for the backend API, and MongoDB for data storage.

The application allows users to browse available trips, while authenticated users can perform administrative functions such as adding, updating, and deleting trip information.

The original application provided the core functionality required for the project, but the code review identified several areas that could be improved. The review focused on code structure, error handling, security, validation, database design, and maintainability.

Software Design and Engineering

The original application was organized into separate frontend and backend components, providing a reasonable foundation for maintainability. Express routes separated API endpoints from controller logic, while Angular components were responsible for displaying and interacting with trip data.

However, several areas could be improved. Some of the original backend code used basic error handling and returned database errors directly to the client. This could expose unnecessary implementation details and make responses less consistent.

Authentication and authorization were another area identified during the review. Administrative operations such as creating, updating, and deleting trips should be protected so unauthorized users cannot modify application data.

The code also contained opportunities for improved documentation and consistency. Adding clearer comments and organizing repeated functionality would make the application easier for another developer to understand and maintain.

Planned Improvement

The planned enhancement was to improve the backend structure, error handling, authentication, validation, and documentation while maintaining the application's existing functionality.

Algorithms and Data Structures

The original application retrieved trips from MongoDB and displayed them to the user. The basic retrieval functionality worked, but there was limited functionality for efficiently locating specific trips from a larger collection.

The application already used MongoDB queries to retrieve individual trips by their trip code. However, the user experience could be improved by providing a search capability that allows users to locate trips based on relevant information.

Planned Improvement

The planned enhancement was to add search functionality that would allow users to more easily locate relevant trip information. This would demonstrate algorithmic problem solving and practical data retrieval techniques.

Databases

The original application used MongoDB with Mongoose to store and manage trip information. The database structure provided the necessary fields for displaying destinations, including the trip code, name, length, resort, price, image, and description.

The review identified opportunities to improve data integrity through stronger schema validation. Some fields had limited restrictions on the values that could be stored, which could allow incomplete or inconsistent data to enter the database.

The original schema also provided an opportunity to improve database reliability through appropriate constraints and indexing. Trip codes should uniquely identify individual trips and therefore are appropriate candidates for a unique database index.

Planned Improvement

The planned database enhancement was to strengthen the Mongoose schema through validation, data integrity rules, appropriate indexing, and improved data handling.

Overall Code Review Findings

  • Strengthen authentication and protect administrative API operations.
  • Improve error handling and response consistency.
  • Strengthen input validation.
  • Improve database integrity and reliability.
  • Add search capabilities.
  • Improve maintainability and documentation.
