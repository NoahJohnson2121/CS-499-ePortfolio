Milestone Four: Enhancement Three — Databases

July 29, 2026

Artifact Description

The artifact selected for my database enhancement is the Travlr Getaways full-stack web application that I originally developed during CS-465 Full Stack Development. This application was created as part of my Computer Science coursework and uses a MEAN stack architecture consisting of MongoDB, Express.js, Angular, and Node.js. The application allows users to view travel destinations while providing administrative functionality for managing trip information through database-driven operations.

The database component of this application uses MongoDB with Mongoose to define and manage trip data. The original artifact contained a functional database structure with CRUD operations, but there were opportunities to improve data integrity, validation, and database performance.

Why I Selected This Artifact

I selected the Travlr Getaways application for my ePortfolio because it demonstrates multiple areas of computer science, including software engineering, algorithms, and database development. The artifact represents my ability to build a complete full-stack application and improve an existing solution through analysis and refinement.

For the database enhancement, I focused on improving the reliability of the MongoDB data layer. The original database implementation stored trip information successfully but did not enforce enough validation rules to ensure consistent data.

Database Enhancements

I enhanced the Mongoose trip schema by adding stronger validation requirements to the application's database fields. Required fields, length restrictions, trimming, and other validation rules were added to help prevent incomplete or inconsistent trip information from being stored in the database.

I also improved the trip code field by enforcing consistent formatting and adding a unique database constraint. This prevents multiple trips from being created with the same identifier and improves the overall integrity of the database.

These changes were intentionally focused on practical improvements rather than introducing unnecessary complexity. The goal was to make the existing database more reliable while preserving the functionality of the original Travlr Getaways application.

Reflection on the Enhancement Process

The process of improving the database component of the Travlr Getaways application helped me better understand the importance of database design decisions beyond simply storing and retrieving information. I learned that databases require careful planning to maintain data quality, improve reliability, and support future application growth.

One challenge I faced during this enhancement was determining the appropriate level of database modification. While there are many advanced database techniques available, I focused on practical improvements that benefited the existing application without introducing unnecessary complexity.

I also encountered and resolved an issue involving duplicate MongoDB index definitions. Resolving this issue helped reinforce the importance of understanding how database configurations interact with Mongoose and how small configuration changes can affect an application's database behavior.
